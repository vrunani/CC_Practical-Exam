🖥️ Unit 2 – Virtualization
What is virtualization?▼
Virtualization is the process of creating a software-based (virtual) representation of something — such as servers, storage, networks, or operating systems — rather than a physical one.

A hypervisor (VMM – Virtual Machine Monitor) sits between hardware and the OS, allowing multiple VMs to run on one physical machine.

🎯 Key benefit: Better resource utilization, isolation, and cost savings by running multiple OS instances on one machine.
Types of Virtualization▼
1. Full Virtualization – Guest OS runs unmodified; hypervisor translates all privileged instructions. (VirtualBox, VMware)
2. Para-Virtualization – Guest OS is modified to work cooperatively with hypervisor (Xen). Faster but needs OS modification.
3. OS-level Virtualization (Containers) – Shares host OS kernel; lightweight isolation (Docker, LXC).
4. Hardware-assisted Virtualization – CPU provides VT-x / AMD-V extensions; hypervisor uses hardware support (KVM).
5. Storage Virtualization – Pools physical storage into logical units (SAN).
6. Network Virtualization – Combines network resources (SDN, VLANs).

Docker Architecture – explain▼
Docker follows a client-server architecture:

Docker Client – CLI tool you use (docker run, docker build). Sends commands to daemon via REST API.
Docker Daemon (dockerd) – Background service that manages images, containers, networks, volumes.
Docker Registry – Stores Docker images (Docker Hub is public; ECR, ACR are private registries).
Docker Objects:
  • Image – Read-only template (like a blueprint)
  • Container – Running instance of an image
  • Dockerfile – Script to build an image
  • Volume – Persistent storage for containers
🐳 Docker uses Linux namespaces for isolation and c-groups for resource limits — no separate OS needed per container.

What is KVM? Draw KVM Architecture.▼
KVM (Kernel-based Virtual Machine) is a Type 1 hypervisor built into the Linux kernel. It converts Linux into a bare-metal hypervisor.

Hardware (CPU with VT-x/AMD-V)
↓
Linux Kernel + KVM Module (/dev/kvm)
↓
QEMU (I/O device emulation)
↓
Guest VMs (each with vCPU, vRAM, vDisk)
KVM uses QEMU for I/O emulation and libvirt as the management API layer.
AWS EC2, EBS, S3 – overview▼
EC2 (Elastic Compute Cloud) – Virtual servers (VMs) in the cloud. Choose OS, CPU, RAM. You pay per hour. Examples: t2.micro, m5.large.

EBS (Elastic Block Store) – Persistent block storage attached to EC2 instances. Like a virtual hard drive. Data persists even if instance stops.

S3 (Simple Storage Service) – Object storage service. Stores files, backups, static websites. Virtually unlimited capacity. Accessible via URL.

Cloud Deployment Models▼
1. Public Cloud – Owned and operated by third-party (AWS, Azure, GCP). Resources shared across customers. Cost-effective.
2. Private Cloud – Dedicated to one organization. Hosted on-premises or by provider. More secure, more expensive.
3. Hybrid Cloud – Combination of public + private. Data moves between both. Supports cloud bursting.
4. Community Cloud – Shared among organizations with common goals (e.g., government agencies, hospitals).
💡 Hybrid = flexibility. Private = control. Public = cost savings. Community = shared compliance.
What is SLA (Service Level Agreement)?▼
An SLA is a formal contract between the cloud service provider and the customer that defines:

• Uptime guarantee – e.g., 99.9% availability ("three nines")
• Response time – how fast issues are addressed
• Performance metrics – CPU, storage, bandwidth benchmarks
• Penalties – compensation if provider fails (service credits)
• Security requirements – data protection obligations

📋 Example: AWS S3 SLA promises 99.9% monthly uptime. If they fall below, customers get service credits.
Essential characteristics of cloud computing (NIST)▼
1. On-demand self-service – Provision resources without human interaction
2. Broad network access – Accessible over the network via standard mechanisms
3. Resource pooling – Shared resources serve multiple consumers (multi-tenancy)
4. Rapid elasticity – Scale up/down quickly based on demand
5. Measured service – Pay-as-you-go; usage is metered and monitored

MongoDB stores data as JSON-like documents (BSON) in collections.

Create: db.students.insertOne({name:"Alice", age:20})

Map-Reduce concept with example▼
MapReduce is a programming model for processing large datasets in parallel across a cluster.

Map phase – Splits input data into key-value pairs
Shuffle phase – Groups all values with the same key
Reduce phase – Aggregates values per key

Example – Word Count:
Input: "hello world hello"
Map: (hello,1), (world,1), (hello,1)
Shuffle: hello→[1,1], world→[1]
Reduce: hello→2, world→1
📦 Used in Hadoop for big data processing. Enables parallel processing on thousands of nodes.
HDFS – NameNode and DataNode▼
HDFS (Hadoop Distributed File System) stores files across multiple machines.

NameNode (Master):
 • Stores metadata (file names, directory structure, block locations)
 • Does NOT store actual data
 • Single point of failure (use Secondary NameNode for backup)

DataNode (Worker):
 • Stores actual data blocks (default 128MB per block)
 • Reports block info to NameNode via heartbeat
 • Data replicated 3× by default for fault tolerance

📁 Client → NameNode (get block location) → DataNode (read/write data)
CloudSim – Cloudlet, Broker, Host▼
CloudSim is a simulation toolkit for modeling cloud environments in Java.

Key components:
• Datacenter – Physical infrastructure (hosts, storage)
• Host – Represents a physical server with RAM, CPU, bandwidth
• VM (Virtual Machine) – Virtual resource created on a host
• Cloudlet – A unit of work/task submitted by user (has MIPS length, file size)
• DatacenterBroker – Mediates between user (cloudlets) and datacenter (VMs); handles scheduling
• CloudletScheduler – Decides how cloudlets share VM resources (SpaceShared / TimeShared)
🔬 Used in research to test scheduling algorithms without real hardware.
🔗 Unit 4 – SOA & Web Services
SOA characteristics▼
SOA (Service-Oriented Architecture) is an architectural style where software components are built as independent services that communicate over a network.

Key characteristics:
1. Loose coupling – Services are independent, changes in one don't break others
2. Reusability – Services can be reused across different applications
3. Interoperability – Different technologies can work together (Java + .NET)
4. Abstraction – Internal logic hidden from service consumers
5. Discoverability – Services can be found and invoked (via UDDI)
6. Composability – Simple services combined to build complex workflows

WSDL and UDDI – explain▼
WSDL (Web Services Description Language) – An XML document that describes a web service:
 • What operations the service offers
 • Input/output message formats
 • Where the service is located (endpoint URL)
 • What protocol to use

UDDI (Universal Description Discovery and Integration) – A directory/registry where businesses publish and discover web services. Like a "Yellow Pages" for web services.

🔄 Flow: Service Provider creates WSDL → publishes to UDDI → Service Consumer discovers via UDDI → uses WSDL to call service

Data Privacy by Design – principles▼
Privacy by Design means embedding privacy into system design from the start, not as an afterthought.

7 Foundational Principles:
1. Proactive not reactive – prevent privacy violations before they happen
2. Privacy as the default – automatically protect user data
3. Privacy embedded into design – not bolted on afterward
4. Full functionality – privacy AND security (not a trade-off)
5. End-to-end security – data protected throughout lifecycle
6. Visibility and transparency – open about practices
7. Respect for user privacy – keep user-centric
📋 Mandated by GDPR (Article 25). Applies to all cloud systems handling personal data.
🚀 Unit 6 – Advanced Topics
Serverless Computing▼
Serverless computing means you write and deploy functions without managing servers. The cloud provider automatically provisions, scales, and manages infrastructure.

Key characteristics:
• Pay per execution (not per hour)
• Auto-scales to zero (no idle costs)
• Event-driven execution
• No server management

Examples: AWS Lambda, Google Cloud Functions, Azure Functions

⚡ Example: An image upload triggers an AWS Lambda function that automatically resizes the image — no server needed.
Multi-cloud vs Federated Cloud▼
Multi-cloud – Using services from multiple cloud providers independently (AWS + GCP + Azure). No integration between providers; each used for different workloads.

Federated Cloud – Multiple cloud providers interconnected and sharing resources/standards. Workloads can move transparently across providers. Requires common APIs and protocols.

Multi-cloudFederated Cloud
IntegrationNo shared standardsShared standards/APIs
PortabilityManual migrationSeamless migration
GovernancePer-cloudUnified governance
DevOps + Cloud▼
DevOps is a culture/practice that combines Development + Operations to deliver software faster and more reliably.

Cloud enables DevOps through:
• CI/CD pipelines – Automated build, test, deploy (AWS CodePipeline, GitHub Actions)
• Infrastructure as Code (IaC) – Terraform, CloudFormation
• Container orchestration – Kubernetes on cloud (EKS, GKE, AKS)
• Monitoring & Logging – CloudWatch, Prometheus, Grafana
• Rapid scaling – Auto-scaling groups respond to load instantly

🔄 DevOps Loop: Plan → Code → Build → Test → Release → Deploy → Operate → Monitor → Plan...

🧪 Practical Concepts
What is the difference between virsh start, virsh create, and virsh define?EXTRA▼
virsh define <xml> – Registers a VM from XML config (persistent, survives reboot). VM is defined but NOT started.
virsh start <name> – Starts a previously defined (persistent) VM.
virsh create <xml> – Defines AND starts a VM from XML, but it is transient (disappears after shutdown).
virsh shutdown <name> – Gracefully shuts down a VM.
virsh destroy <name> – Force-stops a VM (like pulling the power).
virsh list --all – Lists all VMs (running + stopped).
🖥️ Remember: define = register, start = boot, create = temporary define+start, destroy = force kill.

MongoDB Aggregation Pipeline – explain with exampleEXTRA▼
Aggregation Pipeline processes documents through multiple stages to produce computed results.

Common stages: $match (filter), $group (group by), $sort, $project (select fields), $limit

Example – Find average age per city: db.users.aggregate([
  { $match: { age: { $gt: 18 } } },
  { $group: { _id: "$city", avgAge: { $avg: "$age" } } },
  { $sort: { avgAge: -1 } }
])
🍃 More powerful than simple find(). Used for reports, analytics, data transformations.

🖥️ Virtualization Deep Dive
What are namespaces in Linux? How do they enable containers?EXTRA▼
Linux Namespaces provide isolation for various system resources. Each namespace makes a process think it has its own isolated view of that resource.

Types of Namespaces:
• PID namespace – Process IDs isolated (container has its own PID 1)
• NET namespace – Network interfaces, ports isolated
• MNT namespace – Filesystem mount points isolated
• UTS namespace – Hostname and domain name isolated
• IPC namespace – Inter-process communication isolated
• USER namespace – User/group IDs isolated

Docker uses these + c-groups to create lightweight, isolated containers without a separate OS.
What is the difference between a Docker image and a Docker container?EXTRA▼
Docker Image – A read-only template/blueprint. Built from a Dockerfile. Stored in a registry. Like a class in OOP.

Docker Container – A running instance of an image. Has a writable layer on top. Multiple containers can run from one image. Like an object in OOP.

📦 Image : Container = Class : Object = Recipe : Cake
You can bake multiple cakes (containers) from one recipe (image).

What is an EC2 instance type? Explain t2.micro.EXTRA▼
EC2 instance types define the hardware (CPU, RAM, storage, network) of a virtual server.

Naming: [Family][Generation].[Size]
t2.micro: t = burstable general purpose, 2 = 2nd generation, micro = smallest

Families:
• t (t2, t3) – General purpose, burstable CPU
• m (m5, m6) – Balanced compute/memory
• c (c5, c6) – Compute optimized
• r (r5, r6) – Memory optimized
• p, g – GPU instances (ML/AI)
🆓 t2.micro is in the AWS Free Tier — 750 hours/month free for 12 months.
What is auto-scaling in AWS? How does it work?EXTRA▼
Auto Scaling automatically adjusts the number of EC2 instances based on demand.

Components:
• Launch Template – Defines what type of EC2 instance to launch
• Auto Scaling Group (ASG) – Group of EC2 instances managed together
• Scaling Policies – Rules that trigger scaling (based on CPU%, requests, schedule)
• Min/Max/Desired capacity – Boundaries for scaling

Example: If CPU > 70% → add 2 instances. If CPU < 30% → remove 1 instance.
📈 Auto Scaling + Load Balancer = highly available, cost-efficient architecture. This is how Netflix/Amazon handle traffic spikes.
🔗 Web Services Deep Dive
What is REST API? How do you design a RESTful API?EXTRA▼
REST (Representational State Transfer) is an architectural style for designing networked applications using HTTP.

6 REST Constraints:
1. Client-Server – separation of concerns
2. Stateless – no session stored on server
3. Cacheable – responses should indicate cacheability
4. Uniform Interface – consistent URL structure
5. Layered System – can have proxies, load balancers between client-server
6. Code on Demand (optional) – server can send executable code

RESTful URL Design:
GET /users → list all users
GET /users/5 → get user 5
POST /users → create user
PUT /users/5 → update user 5
DELETE /users/5 → delete user 5

📊 Big Data & CloudSim
What scheduling policies does CloudSim support?EXTRA▼
CloudSim supports two main cloudlet scheduling policies:

1. CloudletSchedulerSpaceShared
 • One cloudlet at a time per VM core
 • Others wait in queue (like a single-lane road)
 • Predictable execution but lower parallelism

2. CloudletSchedulerTimeShared
 • All cloudlets run simultaneously, sharing CPU time (like multitasking)
 • Each gets a fraction of CPU
 • Higher parallelism but each task takes longer

And two VM allocation policies for hosts:
VmAllocationPolicySimple – First fit allocation
VmAllocationPolicyBestFit – Best fit allocation
Explain ACID vs BASE in databasesEXTRA▼
ACID (used in SQL/relational DBs):
• Atomicity – all or nothing (transaction fully succeeds or fully fails)
• Consistency – data always valid per rules
• Isolation – concurrent transactions don't interfere
• Durability – committed data persists even after crash

BASE (used in NoSQL DBs):
• Basically Available – system is always available
• Soft state – state may change without input (replication in progress)
• Eventually consistent – will eventually reach consistency
💡 ACID = bank transactions (strict). BASE = social media feed (availability > perfect consistency).

▼
IAM: Root user = full access (use sparingly). IAM user = restricted by policies. Least privilege principle.

💻 A2 – VirtualBox & A3 – KVMPractical
▼
VirtualBox: GUI-based VM creation. Create → Configure RAM/CPU/Storage → Install ISO → Start. Snapshot = save VM state.
KVM requirement: CPU must support VT-x (Intel) or AMD-V. Check: egrep -c '(vmx|svm)' /proc/cpuinfo
Install KVM: apt install qemu-kvm libvirt-daemon-system virt-manager
Key virsh commands: virsh list --all | virsh start NAME | virsh shutdown NAME | virsh define vm.xml | virsh suspend/resume NAME
VM XML defines: name, memory, vCPU, disk path, network interface, boot order

🔬 A6 – CloudSimPractical
▼
CloudSim is a Java library. Main class extends a simulation class and uses CloudSim.init() to start.
Steps: 1) Init CloudSim 2) Create Datacenter (hosts) 3) Create Broker 4) Create VMs 5) Create Cloudlets 6) Submit to broker 7) Run simulation 8) Print results
Host parameters: RAM, bandwidth, storage, CPU (MIPS), scheduling policy
VM parameters: RAM, bandwidth, MIPS, number of CPUs, CloudletScheduler (SpaceShared/TimeShared)
Cloudlet parameters: length (MIPS), file size (bytes), output size, utilization model
🔑 A7 – Encryption & DecryptionPractical
▼
AES (Symmetric): Same key for encrypt and decrypt. Key sizes: 128, 192, 256 bits. Very fast, used for bulk data.
RSA (Asymmetric): Public key encrypts, private key decrypts. Used for key exchange, digital signatures.
Python: from Crypto.Cipher import AES | cipher = AES.new(key, AES.MODE_CBC, iv) | cipher.encrypt(plaintext)
Hash ≠ Encryption. Hash is one-way (SHA-256, MD5). Encryption is two-way (reversible with key).
🐘 A8 – HadoopPractical
▼
Start Hadoop: start-dfs.sh | start-yarn.sh | jps (check running Java processes)

🔗 A10 – RESTful & SOAP Web ServicesPractical
▼
REST API (Python Flask): @app.route('/users', methods=['GET']) → return jsonify(data)
Test REST: Use Postman or curl — curl -X GET http://localhost:5000/users | curl -X POST -H "Content-Type: application/json" -d '{"name":"Alice"}' http://localhost:5000/users
SOAP: XML-based, uses WSDL. Python: pip install zeep → from zeep import Client → client = Client(wsdl_url)
SOAP message structure: Envelope → Header (optional) + Body (required) + Fault (error info)
Key difference to remember for viva: REST = stateless, flexible, JSON. SOAP = strict protocol, XML, enterprise-grade security.
